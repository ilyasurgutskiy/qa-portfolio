# Severity & Priority — Шпаргалка QA

## SEVERITY

🔴 **Blocker** — система полностью не работает, тестирование невозможно
- Примеры: приложение вылетает при запуске, невозможно войти в систему, сервер не отвечает

🟠 **Critical** — ключевая бизнес-функция сломана, система частично работает
- Примеры: оплата не проходит, нельзя добавить товар в корзину, регистрация не работает

🟡 **Major** — важная функция работает неправильно, но есть обходной путь
- Примеры: API принимает пустые данные вместо ошибки 400, фильтр поиска работает некорректно

🔵 **Minor** — небольшая проблема, не влияет на основной функционал
- Примеры: приложение не работает при VPN, кнопка Назад иногда ведёт не туда

⚪️ **Trivial** — косметический дефект, почти не влияет на пользователя
- Примеры: опечатка в тексте, неправильный цвет кнопки, лишний пробел

---

## БЫСТРЫЙ ВОПРОС ДЛЯ ОПРЕДЕЛЕНИЯ SEVERITY

- Blocker → Система вообще работает?
- Critical → Главная функция работает?
- Major → Функция работает правильно?
- Minor → Есть обходной путь?
- Trivial → Это заметно пользователю?

---

## PRIORITY

- **High** — исправить срочно, до релиза обязательно
- **Medium** — важно исправить, но не блокирует релиз
- **Low** — можно исправить в следующей версии

---

## ВАЖНО: Severity и Priority не всегда совпадают

- Пример 1: опечатка в названии компании → Severity Minor + Priority High (репутация бренда)
- Пример 2: кнопка съехала на главной → Severity Trivial + Priority High (первое что видит пользователь)
